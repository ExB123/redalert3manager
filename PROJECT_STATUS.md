# Статус Red Alert Tournament Manager

## Исходные материалы
- Основные визуальные образцы: 10 страниц Screenshot2.pdf.
- Источник данных: SQLite-дамп rma9tjz4gp-data.sql, а не PostgreSQL.
- В исходном дампе 21 прикладная таблица плюс служебная SeedLog (всего 22 таблицы).
- Основные объёмы: Team 32; Player 96; Match 256; RatingMatch 1 732; Tournament 12; Season 10; RatingLeague 8; Map 16; MapStat 1 043; Rank 24; Achievement 14; GameConfig 15; BackupLog 228; Mail 1 064; Simulation 35.
- Пустые в исходном дампе: Medal, News, WinnerPost, AchievementShowcase, _AchievementToAchievementShowcase. Эти разделы поддерживают создание записей, но исходные записи в дампе отсутствуют.
- Все 1 064 письма в исходной базе относятся к GGanz; типы: transfer, cooperation, congrats, general.
- Пороговые значения званий в исходной базе согласуются с опытом и числом побед игроков. Автоматический пересчёт звания при изменении опыта/побед реализован по этим порогам.

## Реализовано в независимой версии
- Локальная SQLite-база и API для основных сущностей.
- Разделы команд, игроков, рейтингов, рейтинговой лиги, обычных матчей, турниров, сезонов, карт, званий, информации, достижений, медалей, постов победителей и витрины достижений.
- Рейтинговые матчи: поиск соперника для основного игрока, создание дополнительных уникальных пар, массовое создание 20 пар без основного игрока, симуляция ближайших матчей и сохранение результатов.
- Основной игрок по умолчанию — GGanz; настройка сохраняется в GameConfig.
- Завершение обычного матча с проверкой счёта, обновлением статистики, продвижением по сетке и начислением турнирных наград по GameConfig.
- Рейтинг команд с MMR, уровнями и выделением первых трёх мест; рейтинг игроков и цветовое обозначение фракций.
- Статистика карт и фракций на основе сохранённых результатов.
- Финансовые таблицы игроков и команд, настройки правил начислений, рыночная стоимость и прогноз с сохранением в SQLite.
- Почта: фильтрация, чтение/непрочитанные, просмотр предложений, принятие/отклонение трансферных и партнёрских предложений. Принятый трансфер меняет команду игрока и сохраняет решение в метаданных письма.
- Полная резервная копия текущих таблиц SQLite и восстановление с подтверждением в интерфейсе. Старые BackupLog-записи, содержащие только частичные снимки, доступны для просмотра, но не считаются полными копиями.
- Защита завершённых обычных и рейтинговых матчей от случайного редактирования/удаления через обычный CRUD.
- Автоматические проверки API и сборки через GitHub Actions.

## Ограничения, которые нельзя скрывать
- В исходной базе не задано начисление опыта за матч; автоматическое повышение званий использует существующие значения опыта/побед и пороги Rank, но не придумывает новые XP-награды.
- В исходных данных нет правил автоматического выполнения достижений: conditionType и requiredTournamentType пусты у всех 14 записей. Достижения доступны для управления и связывания, но автоматическое награждение не выдумывается.
- Историческая статистика фракций использует текущую фракцию игрока: в исходной базе нет снимка фракции каждого участника на момент каждого матча.
- Финансовые правила и оценки стоимости восстановлены по данным и значениям из PDF; если в исходных данных нет значения, интерфейс не должен подменять его выдуманной суммой.
- Часть ссылок на логотипы/эмблемы в исходном дампе ведёт на Adaptive.ai. Их нужно сохранить в локальных файлах через npm run restore:images и отдельно проверить недоступные ссылки.
- Публичное размещение с общей базой и полноценной авторизацией не считается готовым. До настройки авторизации и защищённой серверной БД не публикуйте сервер API в открытый доступ.
