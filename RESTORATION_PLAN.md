# План полного восстановления Red Alert Tournament Manager

Источник данных: исходный SQLite SQL-дамп `rma9tjz4gp-data.sql`. Рабочий репозиторий: `ExB123/redalert3manager`.

## Обязательные условия

- [ ] Сохранить все исходные записи и идентификаторы; не пересоздавать и не очищать базу при обновлении приложения.
- [ ] Сверить все 21 таблицу и количества записей с SQL-дампом.
- [ ] Сохранить названия разделов и вкладок исходного приложения.
- [ ] У каждой доступной кнопки должен быть реальный результат: переход, поиск/сортировка, обновление, просмотр деталей, создание, редактирование, удаление, сохранение или подтверждение действия.
- [ ] Удаление должно подтверждаться; связанные записи должны обрабатываться согласно внешним ключам.
- [ ] Ошибки API и валидации показывать пользователю понятным сообщением.
- [ ] Не зависеть от Adaptive.ai для загрузки сайта и основных данных; вынести доступные изображения в независимое хранилище/локальные ресурсы.
- [ ] Не помещать базу данных с личными данными и резервные копии в публичный GitHub.
- [ ] Проверить сборку и API после каждого этапа.

## Исходные таблицы SQL

SeedLog, Team, Player, Match, RatingMatch, Tournament, Season, RatingLeague, Map, MapStat, Rank, Achievement, Medal, AchievementShowcase, _AchievementToAchievementShowcase, GameConfig, News, WinnerPost, BackupLog, Mail, Simulation.

Известные исходные количества: Team 32; Player 96; Match 256; RatingMatch 1732; Tournament 12; Season 10; RatingLeague 8; Map 16; MapStat 1043; Rank 24; Achievement 14; GameConfig 15; BackupLog 228; Mail 1064; Simulation 35. Medal, News, WinnerPost, AchievementShowcase и таблица связей витрины достижений пустые в дампе. Не считать пустую таблицу ошибкой: экран должен показывать пустое состояние и позволять добавить запись там, где это уместно.

## Разделы и ожидаемое поведение

- [ ] Главная: сводные показатели и переходы в разделы.
- [ ] Валюта: чтение и изменение параметров/настроек валюты из GameConfig; отображение понятных названий, типов и значений.
- [ ] Звания: полный список, изображения, требования по победам/опыту, CRUD.
- [>] Информация: новости, достижения и медали подключены; добавлены отдельные разделы постов победителей (WinnerPost) и витрины достижений (AchievementShowcase), с CRUD.
- [ ] Карты: каталог карт и статистика карт; просмотр/редактирование карт, изображений и описаний.
- [ ] Матчи: результаты, команды, турнир, карта, раунд, победитель, завершение матча; создание/редактирование/удаление с обновлением связанных данных.
- [ ] Рейтинг: рейтинги команд, игроков, а также фильтры фракций «Альянс», «Союз», «Империя»; корректная сортировка по очкам, победам, уровню и RP.
- [>] Рейтинговая лига: лиги и рейтинговые матчи подключены; статистика фракций теперь рассчитывается из Player. Кабинет игрока требует авторизации, которую ещё предстоит реализовать.
- [ ] Сезоны: просмотр и редактирование дат/активности сезона, связь с турнирами.
- [>] Симулятор: добавлена форма запуска матча по выбранным командам, турниру, карте и вероятностям; результат сохраняется в Simulation. Нужна локальная проверка.
- [ ] Список игроков: поиск, фильтры, карточка игрока и CRUD с корректной связью с командой и званием.
- [ ] Список команд: поиск, сортировка, состав, статистика и CRUD.
- [ ] Ставки: исходная SQL-схема не содержит таблицы ставок. Создать отдельную документированную таблицу для функции ставок только после определения безопасных правил и полей; не имитировать существующие данные.
- [ ] Турниры: CRUD, тип, сезон, участники/матчи и победитель; связанные записи не должны теряться.
